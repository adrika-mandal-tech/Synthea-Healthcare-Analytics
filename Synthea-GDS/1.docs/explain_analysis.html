Synthea Graph Analytics — Detailed Presentation

Executive Summary

This pipeline exports a Neo4j healthcare graph, rebuilds it in memory, runs 56 graph algorithms across 6 families, and produces 55 CSV datasets.

14,753Nodes
92,342Directed Edges
55CSV Datasets
56Algorithms
6Categories
23Relationship Types

Technology Stack

Local Python graph analytics stack. No Neo4j GDS enterprise features used.

Core

  • Python 3.14 — runtime
  • pandas — CSV I/O
  • NumPy — arrays and math
  • SciPy — sparse and linear algebra
  • NetworkX — graph algorithms
  • igraph — C-optimized Leiden

Specialized

  • python-louvain — Louvain
  • leidenalg — Leiden
  • cdlib — community suite
  • scikit-learn — K-Means, FastRP
  • node2vec + gensim — embeddings
  • hdbscan — density clustering
  • Mermaid.js — diagrams

System Architecture

Four phases: export, graph construction, algorithm execution, reporting.

Phase 1: Data Export

Stream Neo4j topology into local CSV files

Two Cypher queries export all nodes and directed relationships with full properties.

graph LR Start((Start)) --> Q1[MATCH n] Q1 --> N[14,753 nodes] Start --> Q2[MATCH a-r-b] Q2 --> R[23 rel types] N --> W1[(nodes.csv)] R --> W2[(relationships.csv)] W1 --> End((Done)) W2 --> End linkStyle default stroke:#fff,stroke-width:1.5px
Every distinct node/relationship property becomes a CSV column.

Phase 2: Graph Construction

Build the right in-memory structure for each algorithm family

Four structures from the same CSV data: directed MultiDiGraph, undirected Graph, igraph, and per-type subgraphs.

graph LR Load[Load CSVs] --> M[MultiDiGraph] Load --> U[Undirected Graph] Load --> I[igraph] Load --> S[23 subgraphs] M --> D1[Directed: PageRank, HITS, Dijkstra, BFS, DFS, DAG] U --> D2[Undirected: Louvain, Leiden, Betweenness, Closeness, Degree, MST, similarity, embeddings] I --> D3[Leiden via leidenalg] S --> D4[HITS by relationship type] linkStyle default stroke:#fff,stroke-width:1.5px
Directed structures preserve flow; undirected structures measure symmetry; igraph gives C-speed.

Analysis & Constraints

Observations

  • Graph is sparse: 0.0453% density, 98,631 undirected edges.
  • Leiden modularity 0.4996 vs Louvain 0.4994 — slightly higher with 15 vs 14 communities.
  • Betweenness is long-tailed: max 0.21365 vs mean 0.000114.
  • WCC = 1 component; SCC = 14,753 components in directed view.
  • 159,278 cliques found despite sparse density.
  • 6 algorithms in manifest require parameters beyond default topology.

Constraints

  • HDBSCAN: No CSV produced. Requires dense numerical features.
  • Memory: In-memory processing limits graph size.
  • Static snapshot: CSVs reflect one point in time.
  • Undirected approximation: Some algorithms lose directional flow.
  • No Neo4j GDS: Server-side optimized algorithms were not used.
