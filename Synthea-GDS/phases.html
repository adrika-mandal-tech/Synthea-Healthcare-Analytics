Phase pipelines

Recent 6-phase workflow

Neo4j graph data is exported into local Synthea CSV files to create a stable, reusable source layer.

Phase 2
Nodes → Edges → Graph

Node and relationship tables are turned into a graph structure with healthcare entities and clinical links.

Phase 3

Graph reasoning is orchestrated so the system can answer structural, influence, and relationship-based questions.

Phase 1 — Data Layer

Synthea export → Neo4j read → CSV graph

This phase creates the project’s trusted source layer. The raw healthcare graph is extracted and materialized into local data files so the analytics pipeline can run from a reproducible, portable dataset instead of a live system dependency.

  • Data export from Neo4j
  • Local files: nodes.csv and relationships.csv
  • Verified graph baseline of 14,753 nodes and 92,342 relationships

Phase 2 — Retrieval / Intelligence

Nodes → Relations → Graph facts

This phase builds the semantic healthcare graph. Labels, connections, and entity relationships are reconstructed into a graph model that supports retrieval, interpretation, and graph-aware analysis.

  • Graph construction using NetworkX / igraph
  • Entity and relationship context creation
  • Healthcare knowledge representation layer

Phase 3 — Agent Workflow

Query → Reason → Action

The agent workflow structures how the system asks questions about the graph, interprets the structure, and chooses the right analytic path. This phase turns raw graph computation into a guided decision process.

  • Graph orchestration workflow
  • Question-driven graph execution
  • Agent-ready retrieval and reasoning layer

Phase 4 — Validation Layer

Claim → Evidence → Validation

Validation ensures the graph-derived answers are trustworthy. Claims are checked against evidence, coverage is measured, and unsupported or suspicious statements are flagged before becoming final output.

  • Claim extraction and evidence matching
  • Coverage scoring and quality checks
  • Hallucination and unsupported-answer detection

Phase 5 — Streamlit MVP

Explore → Inspect → Interact

The MVP phase turns the project into a usable interface. Users can open graph summaries, inspect communities, review entities, and navigate the analysis without needing to read raw data files directly.

  • App shell and page structure
  • Overview, community, and entity views
  • Interactive graph exploration layer

Phase 6 — Reporting / Visualization

Metrics → Visuals → Insight

The final phase converts raw algorithm output into a readable narrative. Visualization, HTML dashboards, and structured explanations make the results understandable to both technical and business stakeholders.

  • Final HTML dashboard and project summaries
  • Generated visuals and interpretation
  • Decision-ready insight package

High-value findings

Recent analysis and insight summary

  • Care activity dominates the graph: Encounters and organizations are the main structural drivers. This shows the network is organized around care delivery and institution coordination rather than isolated patient nodes.
  • Influence is concentrated: The PageRank top nodes include wellness, ambulatory, outpatient, and medication-related nodes, demonstrating that a small set of graph entities carries the largest downstream influence.
  • Meaningful clustering exists: Louvain (14 communities, modularity 0.49797) and Leiden (15 communities) confirm that the healthcare graph organizes into real communities rather than random partitions.
  • One connected healthcare network: Weakly connected components = 1, which signals strong overall connectivity and a single integrated healthcare flow model.
  • Granularity shifts by algorithm: Label Propagation found 46 communities, meaning the graph contains hierarchical structure that different algorithms interpret at different scales.
  • Some algorithms are not failures: HDBSCAN and similar parameter-based methods require richer feature vectors and thus are marked as requires_parameters rather than broken.
